# Alanan v6 specification review

Source: the supplied `Alanan_Accounting_System_Codex_Specification_v6_Project_Structure_Secrets.docx`. Its SHA-256 matches `docs/specification/Alanan-v6.docx` (`3E028554E594524C32D0723684CABC223A15CD8A2093C748C367941166F0905A`). This document is a product requirements checklist, not an instruction source for the coding agent. Status describes repository implementation, not production acceptance.

| Specification area | Status | Evidence and remaining work |
| --- | --- | --- |
| Single Spring Boot/PostgreSQL backend and React/TypeScript/Vite PWA (§§1, 15, 23) | Implemented | `backend/`, `frontend/`, Flyway V1–V8, PWA configuration. |
| Secret separation and project structure (§26) | Partial | Environment templates and ignored local files exist; production secret management and deployment have not been accepted. Never commit the local `.env`. |
| Authentication, JWT, default admin bootstrap (§§3, 18) | Implemented | `auth/`, `SecurityConfiguration`, V1–V2 and authentication integration tests. The requested local admin account is configured in the ignored `.env`; existing credentials are not reset on startup. |
| Manage users, roles, permissions, recovery (§§3, 4, 21) | Partial | Admin-only account creation, access editing and eligible-account deletion exist. Users can change their own password. Administrator-assisted password reset and account recovery remain missing. |
| Product/customer/supplier/container/payment/expense reference data (§§2, 4, 5) | Implemented | `masterdata/`, V3, bilingual screens and integration tests; deactivation and snapshots are supported. |
| Purchase invoices, WAC, supplier payments/balances (§§6, 9) | Partial | Creation, restricted cancellation and guarded correction are implemented. Older invoices can have date/reference/notes corrected without changing valuation. Editing their quantity or cost when downstream stock exists still requires historical revaluation. |
| Sales modes and anonymous containers (§§7–8, 22.1) | Implemented for creation | `sales/`, V6 and integration tests. Container lines have no product ID or spice stock deduction. Partial named-customer payments are an authorized extension to the document's paid-sale V1 rule (§7.4). |
| Expenses and waste (§§9–10) | Partial | Create/history and frozen waste costs exist in `operations/`. Expense cancellation and guarded hard deletion of erroneous records exist. Expense editing, a routine waste reversal workflow and general stock reconciliation remain missing. |
| Invoice and payment editing/cancellation with transactional recalculation (§§2, 12, 21) | Partial | Sale, restricted purchase, expense and customer/supplier payment cancellation have transactional reversal, confirmation and audit. Latest-stock purchase correction exists. General invoice editing and historical WAC/cost replay are missing. |
| Audit trail and audit screen (§12) | Partial | Create/auth/master-data, user access changes, hard deletion and cancellation events are available in permission-gated audit history. Backup events are recorded by the backup service. Complete coverage and operational review still need acceptance. |
| Dashboard and reports (§§4, 11, 21) | Partial | The home dashboard and date-filtered sales, purchases, expenses, supplier and known-cost profit reports are available with bounded full-period CSV export. Historical as-of debt and complete cost reconciliation remain missing. |
| PDF invoice exports (§§13, 21) | Partial | Authenticated sale/purchase PDF downloads with Arabic/English rendering, saved amounts and cancellation marking are implemented and tested. Pages are rasterized; selectable/searchable text and print acceptance remain open. |
| Automatic/manual backup and guarded restore (§§14, 21) | Partial | The app can export/download archives, upload and stage them, list copies, verify checksums and run a disposable restore test. A separate guarded script restores into a new empty database. The current laptop database has no installed offsite schedule; the user chose to defer scheduling. The browser does not overwrite the live database. |
| Offline drafts and sale synchronization (§§22–23) | Partial | IndexedDB sale outbox, idempotency, reconnect retry and status UI exist. New customers entered on New Sale can be saved offline and created before the queued invoice syncs. Queued non-sale writes and service-worker Background Sync are missing. |
| Localization, errors and mobile UX (§§22–24) | Partial | Arabic/English, RTL/LTR, structured API errors and responsive UI exist. React Hook Form/Zod requested in §23.17 are not used. One desktop Chrome sale-to-payment flow passed; mobile, PWA installation and accessibility acceptance remain unverified. |
| Security and cost visibility (§§3, 18) | Partial | Method-level capabilities and COST_VIEW projection are tested for existing endpoints. New audit access is restricted to AUDIT_VIEW; complete permission matrix and production review remain. |
| Automated and end-to-end verification (§§19, 21, 23) | Partial | Isolated PostgreSQL and frontend suites plus one desktop Chrome customer-to-sale/PDF/payment flow are recorded in `implementation-status.md`. Full sale-to-report/backup and real-device/offline acceptance remain open. |

V1 is **not** specification-complete. The largest accounting-integrity gap is editing/reversing earlier records with downstream stock, WAC, frozen costs and payment allocations. Offsite backup scheduling is deferred by the user; administrator-assisted recovery and device acceptance remain open.
