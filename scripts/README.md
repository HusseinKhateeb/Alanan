# Scripts

`dev/Start-Development.ps1` initializes local secrets if needed, loads the ignored root `.env`, starts PostgreSQL when needed and runs the backend. Set `BOOTSTRAP_ADMIN_ENABLED=true` and the username/password variables in `.env` to create a missing development admin without prompts. The optional `-BootstrapAdmin` switch enables the same configured bootstrap. The script restores the calling process environment on exit and never evaluates `.env` content as code. See the root README for requirements.

`backup/Export-Database.ps1 -OutputDirectory <existing offsite folder>` creates a PostgreSQL custom-format archive, checks that `pg_restore` can read its table of contents, and writes a SHA-256 checksum. Set `PGHOST`, `PGPORT`, `PGDATABASE`, `PGUSER`, `PGPASSWORD` and, for Neon, `PGSSLMODE=require` and `PGCHANNELBINDING=require` in the current process before running it. The script never prints credentials or overwrites an existing archive.

To install a daily offsite backup task on Windows, use an existing remote UNC share that the Windows account can write. Run `backup/Install-BackupSchedule.ps1 -OffsiteDirectory '\\server\share\alanan' -PgHostName '<database host>' -PgDatabase '<database>' -PgUser '<database user>' -DailyAt '02:00'` under the account that will own the task. It prompts once for the database password and the Windows account password. The database password is saved with Windows DPAPI for that account; the scheduled task needs the Windows password to reach the network share unattended. The task calls `backup/Invoke-ScheduledBackup.ps1`, which restores its process environment after the export. If execution policy blocks scripts, use `Set-ExecutionPolicy -Scope Process Bypass` in that PowerShell window. Check the task's LastTaskResult and confirm the `.dump` and `.sha256` files appear on the remote share after a manual `Start-ScheduledTask` run.

Run `backup/Test-Restore.ps1 -Archive '<offsite path>\alanan-....dump'` regularly. It verifies the checksum, restores into a new disposable PostgreSQL Docker container, checks the Flyway schema and invoice tables, prints row counts, and removes only that temporary container. It never connects to or overwrites production. A synthetic archive passed this drill during development; an actual offsite archive still needs to be produced and restored after the schedule is installed. Monitor share capacity because retention is not automated. The schedule is not installed until a real offsite share and task account are supplied.
